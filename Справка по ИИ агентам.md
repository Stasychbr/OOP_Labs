# Краткая справка по использованию AI-агентов для программирования

## 1. Чем агент отличается от обычного чата с LLM

Обычная языковая модель получает текстовый запрос и генерирует текстовый ответ:

```text
пользователь
    |
    v
   LLM
    |
    v
текстовый ответ
```

Если необходимо изменить программу, в обычном чате пользователь обычно сам:

1. копирует код в чат;
2. получает предложенные изменения;
3. переносит их в проект;
4. запускает программу;
5. копирует ошибку обратно в чат.

**AI-агент** добавляет между пользователем и языковой моделью программную оболочку — agent harness.

Например:

```text
                    +-------------------+
                    |       LLM         |
                    +---------+---------+
                              ^
                              |
                       результаты команд
                              |
                              v
+------------------------------------------------+
|                 Agent harness                  |
|                                                |
|  чтение файлов          изменение файлов       |
|  поиск по проекту       запуск компилятора     |
|  запуск тестов           работа с Git           |
|  выполнение shell-команд                        |
+------------------------------------------------+
             ^
             |
             v
         ваш проект
```

Поэтому агент может получить задачу вида:

> Добавь в класс Matrix сохранение и загрузку бинарного файла. После изменения собери проект и исправь ошибки компиляции.

После этого harness может самостоятельно выполнить последовательность:

```text
прочитать файлы проекта
        ↓
найти класс Matrix
        ↓
предложить изменение
        ↓
изменить .hpp/.cpp
        ↓
запустить CMake
        ↓
увидеть ошибку компиляции
        ↓
передать ошибку модели
        ↓
исправить код
        ↓
снова запустить сборку
```

Главное отличие заключается не обязательно в самой LLM.

Можно использовать **одну и ту же модель**:

```text
                 Qwen
                /    \
               /      \
           обычный    агент
             чат      OpenCode
```

Агент отличается тем, что модель получает доступ к набору инструментов и может многократно вызывать их в процессе решения задачи.

---

# 2. Что такое agent harness

Agent harness — программа, которая связывает LLM с инструментами.

Она обычно умеет:

- читать файлы проекта;
- искать текст по проекту;
- создавать и изменять файлы;
- запускать программы;
- запускать компилятор и тесты;
- получать вывод терминала;
- работать с Git;
- повторно обращаться к LLM после выполнения команды.

Для первого знакомства можно использовать **OpenCode** — открытый coding agent, работающий из терминала. Он поддерживает как облачные, так и локальные LLM.

[Документация OpenCode](https://opencode.ai/docs/?utm_source=chatgpt.com)

# 3. Самый простой полностью локальный вариант

Один из наиболее простых вариантов:

```text
OpenCode
    |
    | OpenAI-compatible API
    v
LM Studio
    |
    v
локальная LLM
```

В этом варианте:

- **OpenCode** является агентом;
- **LM Studio** запускает нейросеть;
- модель работает на вашем компьютере;
- отдельный платный API не требуется.

LM Studio умеет запускать локальный HTTP-сервер с OpenAI-compatible API. По умолчанию в документации используется адрес:

```text
http://localhost:1234/v1
```

# 4. Выбор модели

Для coding agent желательно использовать модель размером примерно **7–8 млрд параметров**, если оборудование это позволяет.

В качестве простого варианта можно попробовать:

**Qwen2.5-Coder-7B-Instruct**

Это специализированная coding-модель семейства Qwen размером около 7.6 млрд параметров.

[Qwen2.5-Coder-7B-Instruct на Hugging Face](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct?utm_source=chatgpt.com)

При использовании LM Studio или `llama.cpp` обычно следует выбрать **GGUF-квантизацию** модели.

Если модель такого размера работает слишком медленно или не помещается в память, можно попробовать модель около 4 млрд параметров:

**Qwen3-4B-Instruct-2507**

[Qwen3-4B-Instruct-2507 на Hugging Face](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507?utm_source=chatgpt.com)

Также существуют небольшие instruction-tuned модели семейства Gemma, например Gemma 3 4B.

### Важно: Base и Instruct — не одно и то же

При самостоятельном поиске модели следует выбирать вариант с обозначением:

```text
Instruct
```

или, в некоторых семействах:

```text
it
```

Например:

```text
Qwen2.5-Coder-7B            <- base-модель
Qwen2.5-Coder-7B-Instruct   <- instruction-tuned модель
```

Для чата и агента нужна именно **instruction-tuned** версия.

Base-модели не проходят специальное instruction tuning и поэтому обычно хуже подходят для диалога, выполнения команд и работы внутри агента.

# 5. Вариант 1: LM Studio

LM Studio — наиболее простой способ локально запустить LLM через графический интерфейс.

[LM Studio](https://lmstudio.ai/)

Общий порядок работы:

```text
1. Установить LM Studio
2. Найти нужную Instruct-модель
3. Скачать подходящую GGUF-квантизацию
4. Загрузить модель
5. Открыть Developer
6. Запустить Local Server
```

После запуска сервер обычно доступен по адресу:

```text
http://127.0.0.1:1234/v1
```

LM Studio удобно использовать для первого знакомства, так как оно позволяет искать, скачивать и запускать модели без ручной работы с командной строкой.

# 6. Выбор квантизации

Локальные модели часто распространяются в формате GGUF в нескольких вариантах квантизации.

Квантизация уменьшает объем памяти, необходимый для хранения модели, за счет хранения весов с меньшей точностью.

Упрощенно:

```text
более высокая точность
        |
        | больше памяти
        | обычно немного выше качество
        v

FP16
Q8
Q6
Q5
Q4
Q3
Q2

        ^
        | меньше памяти
        | обычно ниже качество
        |
более сильная квантизация
```

Для первого запуска рекомендуется выбирать примерно 4-битные варианты.

Хорошие варианты по умолчанию:

```text
Q4_K_M
Q4_K_XL
```

`Q4_K_M` — хороший универсальный компромисс между размером модели, скоростью и качеством.

`Q4_K_XL` обычно занимает немного больше памяти, но может сохранять качество несколько лучше. Если памяти достаточно, можно попробовать его.

Для большинства учебных экспериментов нет необходимости сразу скачивать FP16-версию модели.

Например, вместо очень большой модели:

```text
Qwen2.5-Coder-7B-Instruct FP16
```

разумнее начать с:

```text
Qwen2.5-Coder-7B-Instruct Q4_K_M
```

или:

```text
Qwen2.5-Coder-7B-Instruct Q4_K_XL
```

Если модель все равно не помещается в память или работает слишком медленно, лучше сначала перейти на модель меньшего размера, например с 7–8 млрд параметров на 4 млрд, а не использовать слишком агрессивную квантизацию.

При поиске модели необходимо обращать внимание одновременно на:

```text
1. размер модели;
2. наличие Instruct-версии;
3. формат GGUF;
4. вариант квантизации.
```

# 7. Вариант 2: llama.cpp

Вместо LM Studio можно использовать `llama.cpp`.

Это более низкоуровневый вариант, в котором модель запускается непосредственно из командной строки.

[llama.cpp](https://github.com/ggml-org/llama.cpp)

`llama.cpp` умеет:

* загружать GGUF-модели;
* выполнять inference на CPU и GPU;
* использовать квантизованные модели;
* запускать HTTP-сервер;
* предоставлять OpenAI-compatible API.

После установки сервер можно запустить примерно так:

```bash
llama-server \
    -m model.gguf \
    --port 8080
```

После этого модель становится доступна по адресу:

```text
http://127.0.0.1:8080/v1
```

Дальше OpenCode можно подключить к этому адресу так же, как к любому OpenAI-compatible API.

LM Studio и `llama.cpp` решают по сути одну задачу:

```text
локальная модель
      |
      v
HTTP API
      |
      v
OpenCode
```

Разница в основном в интерфейсе:

```text
LM Studio
    -> графический интерфейс
    -> проще для первого запуска

llama.cpp
    -> командная строка
    -> больше контроля
    -> лучше показывает, что именно происходит внутри
```

Для первого знакомства рекомендуется начать с LM Studio, а `llama.cpp` использовать как альтернативу.

# 8. Установка OpenCode

Один из вариантов установки:

```bash
npm install -g opencode-ai
```

Также официальный установщик:

```bash
curl -fsSL https://opencode.ai/install | bash
```

Доступны и другие варианты установки, включая Homebrew.

После установки в каталоге проекта можно запустить:

```bash
opencode
```

# 9. Подключение OpenCode к LM Studio

OpenCode имеет готовую поддержку LM Studio.

В конфигурации `opencode.json` можно определить локального провайдера примерно так:

```json
{
  "$schema": "https://opencode.ai/config.json",

  "provider": {
    "lmstudio": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "LM Studio (local)",

      "options": {
        "baseURL": "http://127.0.0.1:1234/v1"
      },

      "models": {
        "MODEL_ID": {
          "name": "Local model"
        }
      }
    }
  }
}
```

Вместо:

```text
MODEL_ID
```

нужно указать идентификатор модели, который использует LM Studio.

После запуска OpenCode модель можно выбрать командой:

```text
/models
```

Теперь OpenCode будет отправлять запросы локальной модели.

# 10. Если компьютер не позволяет запустить локальную модель

Локальный запуск не является обязательным для знакомства с агентами.

Можно воспользоваться облачным coding agent или AI-ассистентом.

### OpenAI Codex

Codex — coding agent OpenAI.

На данный момент Codex включен в планы ChatGPT, в том числе **Free**, но количество токенов сильно ограничено.

[Информация об использовании Codex с планами ChatGPT](https://help.openai.com/en/articles/11369540?utm_source=chatgpt.com)

Для первого знакомства это один из самых простых вариантов: локальную модель и inference-сервер настраивать не требуется.

---

### GitHub Copilot

GitHub предоставляет бесплатный **Copilot Free**, а для подтвержденных студентов доступен **Copilot Student**. Бесплатные планы имеют ограничения по использованию; GitHub также предоставляет agent mode и другие агентные функции в зависимости от плана.

[Планы GitHub Copilot](https://docs.github.com/en/copilot/get-started/plans?utm_source=chatgpt.com)

Если есть подтвержденный статус студента, стоит отдельно посмотреть условия **Copilot Student**.

---

### GigaCode

Еще один вариант — GigaCode от GitVerse.

Он поддерживает в том числе C и C++.

[GigaCode](https://gitverse.ru/features/gigacode/?utm_source=chatgpt.com)

Актуальные условия доступа и ограничения следует смотреть на странице сервиса.

---

### SourceCraft Code Assistant

SourceCraft Code Assistant предоставляет чат, интеграцию с IDE, CLI и агентный режим. В документации также указывается использование OpenCode внутри SourceCraft CLI.

[SourceCraft Code Assistant](https://sourcecraft.dev/portal/code-assistant/?utm_source=chatgpt.com)

Этот вариант удобен, если хочется попробовать готовый сервис без самостоятельного запуска LLM.

# 11. Что важно понять из эксперимента

Цель знакомства с агентами — не получить максимально качественно написанную лабораторную работу.

Полезнее понять архитектуру:

```text
              LLM
               ^
               |
               | prompt / tool result
               |
               v
        +--------------+
        |    Agent     |
        |   harness    |
        +--------------+
          /     |     \
         /      |      \
      files    shell    git
        |        |       |
        +--------+-------+
                 |
              project
```

LLM сама по себе в основном генерирует последовательность токенов.

Возможность:

```text
прочитать файл
изменить файл
запустить программу
посмотреть ошибку
исправить программу
```

появляется благодаря окружающей ее **агентной инфраструктуре**.

Поэтому качество coding agent определяется не только выбранной нейросетью, но и:

- набором доступных инструментов;
- качеством передачи контекста;
- способностью модели корректно вызывать инструменты;
- размером контекстного окна;
- правилами работы самого harness;
- качеством обратной связи от компилятора и тестов.

Маленькая локальная модель на 4–8 млрд параметров может заметно уступать крупным облачным моделям, особенно при длинных агентных цепочках. Для первого знакомства это не проблема: цель эксперимента — увидеть сам принцип работы системы.
