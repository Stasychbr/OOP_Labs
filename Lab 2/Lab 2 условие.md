## 1. Индексация матрицы

Матрица из работы 1 хранит данные плоским массивом, а моделям нужны строки —
объекты выборки. Перегрузите у матрицы `operator[]` так, чтобы `m[i]`
возвращал `std::span<const double>` — `i`-ю строку без копирования данных; тогда
обращение к отдельному элементу запишется как `m[i][j]` и сработает через
`operator[]` самого `span`. Нужны две перегрузки, константная и неконстантная, причём
границы `operator[]` не проверяет — как и у стандартных контейнеров. Для
проверяемого доступа заведите отдельный метод `at()`, бросающий исключение.

## 2. Метрики расстояния

Метрика расстояния — самостоятельная сущность со своим интерфейсом, а не
параметр-перечисление внутри модели.

```cpp
class IDistance
{
public:
    virtual ~IDistance() = default;

    virtual double compute(
        std::span<const double> a,
        std::span<const double> b
    ) const = 0;
};
```

Реализуются минимум три метрики: евклидова, манхэттенская и Чебышёва.

Требования:

1. Модель принимает метрику извне и не знает, какая именно ей передана.
   Добавление новой метрики не требует изменения кода модели.
2. Владение метрикой организовано явно и объяснимо: либо модель владеет ею через
   умный указатель, либо метрика передаётся по ссылке и живёт дольше модели.
   Выбранный вариант обосновывается в README.
3. Несовпадение размерностей векторов не остаётся незамеченным.

## 3. Поиск соседей

Расстояния до всех обучающих объектов считаются перебором. Вопрос в том, как из
`n` посчитанных расстояний выбрать `k` наименьших.

### Как это делается

| Способ | Время | Дополнительная память |
|---|---|---|
| Полная сортировка всех расстояний | `O(n log n)` | `O(n)` |
| `std::nth_element` по массиву расстояний | `O(n)` в среднем | `O(n)` |
| Куча размера `k`, заполняемая на лету | `O(n log k)` | `O(k)` |

Полная сортировка бессмысленна: вам не нужен порядок всех `n` объектов, нужны
только `k` лучших, а `k` обычно единицы при `n` в тысячах. Поэтому полная
сортировка в этой работе запрещена.

Оставшиеся два способа отличаются тем, нужно ли хранить все расстояния.
`std::nth_element` работает по уже готовому массиву из `n` пар «расстояние,
индекс». Куча позволяет не собирать этот массив вовсе.

### Требуемая реализация: куча размера k

Заводится максимальная куча ёмкостью `k`, в вершине которой лежит худший из
текущих кандидатов. Один проход по обучающей выборке:

1. Посчитать расстояние до очередного объекта.
2. Если в куче меньше `k` элементов — добавить.
3. Иначе, если расстояние меньше, чем у вершины, — удалить вершину и добавить
   новый элемент.
4. Иначе — ничего не делать.

После прохода в куче ровно `k` ближайших объектов. Каждая операция стоит
`O(log k)`, и она выполняется далеко не для каждого объекта: как только куча
заполнена хорошими кандидатами, большинство объектов отсеивается одним
сравнением с вершиной.

Требования:

1. Используется `std::priority_queue` или `std::make_heap` / `std::push_heap` /
   `std::pop_heap` над `std::vector`. Компаратор задаётся лямбдой.
2. Массив всех `n` расстояний не хранится: память под поиск соседей —
   `O(k)`, а не `O(n)`.
3. Результат детерминирован. При равных расстояниях порядок определяется
   однозначно — например, сравнением по индексу объекта при равенстве
   расстояний. Правило реализуется прямо в компараторе.

Обратите внимание на направление сравнения в `std::priority_queue`.

### Замечание про деревья

Библиотеки вроде scikit-learn используют деревья — kd-tree и
ball-tree, которые строятся по обучающим
данным. Дерево разбивает пространство на области и позволяет
при запросе не обходить всю выборку.

Работает это хорошо в низкой размерности. При десятке признаков, а тем более
после one-hot кодирования, выигрыш быстро исчезает: в многомерном пространстве
почти все объекты оказываются примерно одинаково далеко, и дерево вынуждено
обходить почти всё. Поэтому в этом курсе мы честно перебираем все объекты, а
экономим на выборе `k` лучших. Знать про существование таких структур полезно,
реализовывать их не требуется.

## 4. Иерархия моделей

Появляется базовый интерфейс модели, общий для всего курса:

```cpp
class IModel
{
public:
    virtual ~IModel() = default;

    virtual void fit(
        const Matrix& features,
        std::span<const double> target
    ) = 0;

    virtual std::vector<double> predict(
        const Matrix& features
    ) const = 0;
};
```

От него наследуются `KnnRegressor` и `KnnClassifier`.

Требования:

1. Общая часть — хранение обучающей выборки, метрика, значение `k`, поиск
   соседей — не дублируется в обоих классах.
2. Различие между регрессией и классификацией сосредоточено в одном месте: в
   способе получить ответ по найденным соседям.
3. Выбор между наследованием от общей базы и вынесением поиска соседей в
   отдельный класс-помощник обоснован в README. Оба решения допустимы, но
   объяснить своё нужно.
4. Интерфейс `IModel` не содержит ничего специфичного для kNN: в работе 3 его
   будет реализовывать совсем другая модель.

## 5. Предсказание

**Регрессия:** ответ — среднее значений отклика у `k` ближайших соседей.

**Классификация:** ответ — наиболее частый класс среди `k` ближайших соседей.
Подсчёт голосов ведётся через `std::map` или `std::unordered_map`. Ничьи
разрешаются детерминированно.

**Взвешивание:** поддерживаются два режима — равные веса и веса, обратные
расстоянию. Во втором случае отдельно обрабатывается нулевое расстояние
(объект совпал с обучающим), чтобы не возникло деления на ноль.

Способ взвешивания задаётся через `enum class` или отдельный интерфейс — на ваш
выбор, с обоснованием.

## 6. Программа

Приложение выполняет один сценарий:

1. загружает данные, обработанные классом из работы 1;
2. обучает модель на обучающей подвыборке с заданными `k`, метрикой и способом взвешивания;
4. предсказывает ответы для тестовой подвыборки;
5. выводит первые несколько объектов тестовой части: предсказание и настоящее
   значение отклика рядом.

Никаких сводных чисел качества считать не нужно — этим занимается работа 5.
Достаточно, чтобы было видно, что модель обучается и предсказывает
осмысленно.

Покажите на защите, что при разных `k`, разных метриках и разном взвешивании
предсказания меняются.

## 7. Требования к коду

- Стандарт C++20, сборка через CMake, без предупреждений при `-Wall -Wextra`.
- Модели и метрики лежат в библиотеке ядра, вывод и взаимодействие с

- Полиморфизм динамический: работа через указатель или ссылку на базовый класс.
  У полиморфных базовых классов виртуальный деструктор.
- Обучающие данные внутри модели не копируются лишний раз. Решение о том,
  хранит ли модель копию выборки или ссылку на неё, принимается осознанно и
  объясняется.
- Об ошибках ядро сообщает исключениями, см. ниже.
- Тесты в CTest. Специальный фреймворк не требуется. Минимальный набор:
  - каждая метрика расстояния на векторах с известным ответом;
  - поиск соседей: на маленьком наборе куча возвращает ровно те же `k`
    объектов, что и полная сортировка (полная сортировка живёт только в тесте);
  - kNN с `k = 1`, предсказывающий на обучающей выборке, возвращает её же
    значения;
  - регрессия на маленьком наборе, посчитанном вручную (константный или очень простой линейный отклик);
  - взвешивание по расстоянию при совпадении объекта с обучающим не приводит к
    делению на ноль.
  - каждая из ошибочных ситуаций из списка ниже действительно приводит к
    исключению ожидаемого типа.
- В Debug подключены AddressSanitizer и UndefinedBehaviorSanitizer, тесты
  проходят без срабатываний.

### Ошибки и исключения

Начиная с этой работы об ошибках сообщают исключения.

1. Заводится небольшая собственная иерархия исключений, наследуемая от
   стандартных классов (`std::invalid_argument`, `std::out_of_range`,
   `std::runtime_error`). Отдельные типы нужны хотя бы для несовпадения
   размерностей и для некорректного использования модели.
2. Исключение бросается там, где ошибка обнаружена. Коды возврата и флаги
   ошибки для этого не используются.
3. Функции ядра ничего не печатают при ошибке. Единственное место, где
   исключение перехватывается, — `main`: ловит по ссылке на базовый класс,
   печатает `what()` и возвращает ненулевой код.
4. Вести журнал ошибок и записывать их текстом куда-либо не требуется.

Минимальный набор ситуаций, в которых исключение обязательно:

- размерности векторов в метрике не совпадают;
- `k` меньше единицы или больше размера обучающей выборки;
- `predict` вызван до `fit`;
- обучение на пустой выборке;
- при предсказании число признаков не совпадает с тем, на котором обучались;
- выход за границы в `Matrix::at()`.
