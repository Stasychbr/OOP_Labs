## 1. Что требуется сделать

Реализовать решающий пень — дерево решений глубины один — как
реализацию интерфейса `IModel`, для регрессии и для классификации.

```cpp
class IModel
{
public:
    virtual ~IModel() = default;

    virtual void fit(
        const Matrix& features,
        std::span<const double> target
    ) = 0;

    virtual std::vector<double> predict(
        const Matrix& features
    ) const = 0;
};
```

Пень устроен так: выбирается один признак `j` и один порог `t`. Все объекты, у
которых значение `j`-го признака меньше или равно `t`, попадают в левую часть,
остальные — в правую. В каждой части модель предсказывает константу: для
регрессии среднее значений отклика, для классификации самый частый класс.

Обучение — это перебор: нужно найти такую пару (признак, порог), при которой
разбиение получается наилучшим по выбранному критерию.

Собственно вся работа — научиться делать этот перебор быстро.

## 2. Индексация матрицы

Матрица из работы 1 хранит данные плоским массивом, а моделям нужны строки —
объекты выборки. Перегрузите у матрицы `operator[]` так, чтобы `m[i]`
возвращал `std::span<const double>` — `i`-ю строку без копирования данных; тогда
обращение к отдельному элементу запишется как `m[i][j]` и сработает через
`operator[]` самого `span`. Нужны две перегрузки, константная и неконстантная, причём
границы `operator[]` не проверяет — как и у стандартных контейнеров. Для
проверяемого доступа заведите отдельный метод `at()`, бросающий исключение.

## 3. Почему наивная реализация плохая

Наивно алгоритм пишется так:

```text
для каждого признака j:
    для каждого кандидата в пороги t:
        пройти по всей выборке, разложить объекты на левые и правые
        посчитать критерий
```

Кандидатов в пороги примерно `n` (между каждой парой соседних значений), и на
каждого тратится проход по всей выборке. Получается `O(n^2)` на признак и
`O(d * n^2)` всего. При `n = 1000` это уже миллион операций на признак, при
`n = 10000` — сто миллионов, и пень начинает обучаться заметно долго. А в
работе 4 вы будете строить лес из сотен деревьев, каждое из которых состоит из
множества таких разбиений.

Требуемая сложность: `O(n log n)` на признак, то есть `O(d * n log n)` всего,
при дополнительной памяти `O(n)`.

---

## 4. Ключевая идея

Идея состоит из двух частей.

**Первая: отсортировать значения признака один раз.** После сортировки все
кандидаты в пороги идут по возрастанию, и при переходе к следующему порогу
ровно один объект переезжает из правой части в левую. Ничего больше не
меняется.

**Вторая: считать критерий не по объектам, а по агрегатам.** Если критерий
выражается через несколько накопленных чисел (сумма, количество, счётчики
классов), то при переезде одного объекта эти числа обновляются за `O(1)` — и
критерий считается за `O(1)` вместо прохода по выборке.

Таким образом один проход по отсортированному признаку перебирает все пороги за
`O(n)`, а всю стоимость составляет сортировка — `O(n log n)`.

Осталось выразить критерии через агрегаты. Это делается для обеих задач, и
результат довольно приятный.

## 5. Критерий для регрессии

Качество разбиения для регрессии — суммарная ошибка предсказания константой в
каждой части:

```text
SSE = Σ_left (y_i - mean_L)^2  +  Σ_right (y_i - mean_R)^2
```

Раскроем скобки для одной части. Пусть в ней `m` объектов, `S` — сумма их
значений отклика, `Q` — сумма квадратов:

```text
Σ (y_i - S/m)^2 = Q - S^2 / m
```

Сложим обе части. Величина `Q_L + Q_R` — это сумма квадратов по всей выборке,
она не зависит от того, где мы поставили порог. Значит:

```text
SSE = Q_all - ( S_L^2 / m_L  +  S_R^2 / m_R )
```

Первое слагаемое постоянно. Поэтому **минимизировать SSE — это то же самое, что
максимизировать**

```text
G = S_L^2 / m_L  +  S_R^2 / m_R
```

Здесь важно то, чего в формуле нет: сумм квадратов. Достаточно поддерживать
сумму значений и количество объектов в левой части; правая получается
вычитанием из общей суммы и общего количества.

Обновление при переезде объекта со значением отклика `y`:

```text
S_L += y;   m_L += 1;
S_R = S_всего - S_L;   m_R = n - m_L;
```

Две операции сложения — и критерий пересчитывается за `O(1)`.

Побочная выгода: формула `Q - S^2/m` численно неустойчива при больших значениях
отклика (вычитание близких чисел), а в итоговой формуле `Q` вообще не участвует,
так что проблема исчезает сама.

## 6. Критерий для классификации

Для классификации используется индекс Джини. Для части с `m` объектами и
счётчиками классов `n_c` (c - метки классов):

```text
Gini = 1 - Σ_c (n_c / m)^2
```

Качество разбиения — взвешенная сумма:

```text
Crit = m_L * Gini_L + m_R * Gini_R
```

Подставим и раскроем. Обозначим `A = Σ_c n_c^2` для части:

```text
m * Gini = m - A / m

Crit = n - ( A_L / m_L  +  A_R / m_R )
```

Первое слагаемое снова постоянно, поэтому **минимизировать критерий — это то же
самое, что максимизировать**

```text
H = A_L / m_L  +  A_R / m_R
```

Теперь обновление. Когда объект класса `c` переезжает из правой части в левую,
меняется только слагаемое для класса `c`. Пусть до переезда в левой части было
`a` объектов класса `c`, в правой — `b`. Тогда:

```text
A_L += 2*a + 1;      (потому что (a+1)^2 = a^2 + 2a + 1)
A_R += 1 - 2*b;      (потому что (b-1)^2 = b^2 - 2b + 1)
m_L += 1;  m_R -= 1;
```

Снова `O(1)`, независимо от числа классов.

Джини предпочтительнее энтропии ввиду более низкой вычислительной сложности. 
В реализациях деревьев он используется обычно по умолчанию.

Чтобы работать со счётчиками по индексу, метки классов удобно один раз
перенумеровать подряд — от нуля. Это же пригодится в работах 3 и 4.

## 7. Алгоритм целиком

```text
обучение(X, y):
    посчитать общие агрегаты по всей выборке
    лучший = пусто

    для каждого признака j:
        order = индексы объектов, отсортированные по X[i][j]
        обнулить агрегаты левой части, правую взять равной общей

        для позиции p от 0 до n-2:
            i = order[p]
            перенести объект i из правой части в левую (обновить агрегаты)

            если X[order[p]][j] == X[order[p+1]][j]:
                продолжить          // порога между равными значениями нет

            если m_L < min_samples_leaf или m_R < min_samples_leaf:
                продолжить

            score = критерий по текущим агрегатам        // O(1)
            t = середина между X[order[p]][j] и X[order[p+1]][j]

            если score лучше найденного:
                запомнить (j, t, score)

    по лучшему разбиению посчитать предсказания в левой и правой частях
```

Важные детали:

- **Сортируются индексы, а не данные.** Матрица признаков не меняется, вы
  сортируете вспомогательный вектор `std::vector<std::size_t>` с лямбдой в
  качестве компаратора. Буфер выделяется один раз и переиспользуется для всех
  признаков.
- **Проверка на равенство идёт после переноса объекта, но до вычисления
  критерия.** Если этого не сделать, вы поставите порог между двумя одинаковыми
  значениями, и часть объектов уедет не в ту сторону: в предсказании они
  сравниваются с порогом заново и попадут не туда, где их учли при обучении.
  Это важно.
- **Порог — середина между соседними различными значениями**, а не само
  значение. Считать лучше как `a + (b - a) / 2`, а не `(a + b) / 2`: вторая
  формула переполняется при больших числах. Еще лучше - использовать `std::midpoint`.
- **Цикл идёт до `n-2` включительно**: последнее положение порога — между
  предпоследним и последним объектом, справа должен остаться хотя бы один.
- Агрегаты правой части не нужно поддерживать отдельно, если они получаются
  вычитанием из общих. Это меньше кода и меньше мест, где можно ошибиться.

## 8. Интерфейс

Пень — обычная реализация интерфейса модели:

```cpp
enum class SplitCriterion { Variance, Gini };

class DecisionStump : public IModel
{
public:
    DecisionStump(SplitCriterion criterion, std::size_t min_samples_leaf);

    void fit(const Matrix& features, std::span<const double> target) override;
    std::vector<double> predict(const Matrix& features) const override;

    std::size_t split_feature() const;
    double split_threshold() const;
};
```

Доступ к выбранному признаку и порогу нужен не модели, а вам: без него
невозможно ни проверить результат в тесте, ни показать на защите, что пень
нашёл осмысленное разбиение.

## 9. Граничные случаи

Обрабатываются явно, каждый закрыт тестом:

- все значения признака одинаковы — по этому признаку допустимых порогов нет;
- все значения всех признаков одинаковы — допустимого разбиения нет вообще,
  модель предсказывает константу по всей выборке и сообщает об этом;
- `min_samples_leaf` не позволяет ни одного разбиения — поведение то же;
- несколько разбиений дают одинаковое значение критерия — выбор
  детерминирован (например, меньший индекс признака, затем меньший порог);
- в выборке один объект или один класс.

### Ошибки и исключения

Начиная с этой работы об ошибках сообщают исключения.

1. Заводится небольшая собственная иерархия исключений, наследуемая от
   стандартных классов (`std::invalid_argument`, `std::out_of_range`,
   `std::runtime_error`). Отдельные типы нужны хотя бы для несовпадения
   размерностей и для некорректного использования модели.
2. Исключение бросается там, где ошибка обнаружена. Коды возврата и флаги
   ошибки для этого не используются.
3. Функции ядра ничего не печатают при ошибке. Единственное место, где
   исключение перехватывается, — `main`: ловит по ссылке на базовый класс,
   печатает `what()` и возвращает ненулевой код.
4. Вести журнал ошибок и записывать их текстом куда-либо не требуется.

Минимальный набор ситуаций, в которых исключение обязательно:

- число объектов в матрице признаков и длина вектора откликов не совпадают;
- `predict` вызван до `fit`;
- обучение на пустой выборке;
- `min_samples_leaf` меньше единицы;
- при предсказании число признаков не совпадает с тем, на котором обучались;
- выход за границы в `Matrix::at()`.

## 12. Тесты

- **Сравнение с наивной реализацией.** Главный тест. Пишется медленная
  реализация, которая для каждого порога честно проходит по всей выборке, и на
  случайных данных (несколько десятков объектов, несколько признаков, разные
  значения `min_samples_leaf`) проверяется, что она и быстрая находят одно и то
  же разбиение с точностью до сравнения вещественных чисел. Наивная реализация
  живёт только в тестах.
- Искусственные данные, разделимые по одному признаку: пень находит именно этот
  признак и порог в правильном месте.
- Признак-константа не выбирается, если есть информативный.
- Дубликаты значений признака: пень не ставит порог между равными значениями.
- Пень подставляется в код приложения через `IModel`, без изменений в
  вызывающей стороне.
- Каждая из ошибочных ситуаций из раздела про исключения действительно
  приводит к исключению ожидаемого типа.

верному коду — это ошибка, за которую отвечаете вы.

## 16. Критерий выполнения

Звёздочка засчитана, если:

- пень работает для обеих задач и встраивается в общую иерархию через `IModel`;
- сортировка выполняется один раз на признак, критерий обновляется за `O(1)`,
  дополнительная память `O(n)`;
- тест на совпадение с наивной реализацией проходит;
- граничные случаи обработаны и покрыты тестами, ошибочные ситуации
  приводят к исключениям;
- вы можете объяснить любую строку кода и вывести формулу инкрементального
  пересчёта на доске без подсказок.
