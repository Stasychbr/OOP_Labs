# Лабораторная работа 1. Загрузка, анализ и предобработка табличных данных

## Цель работы

Реализовать консольную программу, которая загружает табличный датасет с
пропущенными значениями, определяет типы признаков, вычисляет и выводит
статистику и по запросу сохраняет предобработанный набор данных.

Эта программа становится основой всех последующих лабораторных работ: модели из
работ 2–5 и графическое приложение из работы 6 будут использовать данные,
подготовленные вашим кодом.

## Выбор датасета

Датасет выбирается самостоятельно в [UCI Machine Learning Repository](https://archive.ics.uci.edu/).

Требования к набору:

- порядка 1000 объектов (допустимо от 500 до 5000);
- порядка 10 признаков (допустимо от 6 до 25);
- есть и числовые, и категориальные признаки;
- есть пропущенные значения хотя бы в одном признаке;
- есть столбец отклика, пригодный для задач регрессии или классификации, — он
  понадобится в следующих работах.

Название набора, ссылка на него, описание признаков и принятое обозначение
пропусков фиксируются в README.

Выбор не окончательный: датасет можно поменять позже в течение семестра, если
исходный оказался неудобным. Требования к набору при этом те же, а изменение
отмечается в README.

## Важное требование: специфичность без хардкода

Программа пишется под конкретный выбранный вами датасет. Не нужно делать
универсальный загрузчик произвольных табличных файлов.

Это означает:

- если в вашем датасете категории закодированы буквами, а пропуски записаны как
  `undefined`, программа ориентируется именно на эти обозначения;
- вы не поддерживаете десяток альтернативных разделителей, кодировок и форматов
  «на всякий случай».

Одновременно программа не должна ломаться от изменений внутри того же формата:

- добавление ещё одного столбца в файл обрабатывается корректно, без правки
  кода;
- изменение порядка столбцов не ломает программу;
- изменение числа строк не ломает программу;
- количество признаков, их имена и типы определяются из файла, а не записаны в
  коде константами.

Обозначения, специфичные для датасета (строка пропуска, разделитель, наличие
строки заголовка), задаются в одном месте — в конфигурации загрузчика, а не
разбросаны по коду в виде литералов.

# Обязательная часть

## 1. Загрузка данных

Программа читает CSV-файл и строит представление датасета в памяти.

Требования:

1. Имена признаков считываются из строки заголовка.
2. Проверяется согласованность файла: одинаковое число полей в каждой строке,
   одинаковая длина всех столбцов. При нарушении — понятное сообщение об ошибке с
   указанием номера проблемной строки.
3. Пропущенные значения распознаются по обозначению, принятому в вашем датасете,
   и представляются явно как отсутствующее значение, а не особым числом вроде
   `-9999` или пустой строкой.
4. Данные хранятся по столбцам, а не по строкам: столбец — это либо числовой,
   либо категориальный признак.

## 2. Автоматическое определение типа признака

Для каждого столбца программа сама решает, числовой он или категориальный.

Правило определения выбираете вы; допустимы, например, такие критерии:

- значения столбца не разбираются как числа — признак категориальный;
- значения разбираются как числа, но число различных значений мало (например,
  меньше порогового значения или меньше заданной доли от числа строк) — признак
  считается категориальным;
- в остальных случаях признак числовой.

Выбранное правило и его порог описываются в README. Правило должно работать на
вашем датасете корректно: если какой-то признак классифицируется неверно, это
нужно либо исправить правилом, либо явно обосновать в README.

## 3. Сводка по датасету

Сразу после загрузки программа выводит в консоль:

- число объектов (строк);
- число признаков;
- список признаков с указанием типа каждого (числовой или категориальный);
- статистику пропусков: по каждому признаку с пропусками — количество и доля
  пропущенных значений.

Пример вывода:

```text
Объектов: 1000
Признаков: 11

  #  Признак        Тип             Пропуски
  0  age            числовой              0
  1  workclass      категориальный       57 (5.7%)
  2  fnlwgt         числовой              0
  3  education      категориальный        0
  ...

Всего пропусков: 138 в 3 признаках
```

Формат таблицы может отличаться, но вся перечисленная информация должна
присутствовать.

## 4. Статистика по выбранному признаку

Программа в цикле запрашивает у пользователя номер признака и выводит по нему
статистику. Должен быть предусмотрен способ завершить цикл.

Для числового признака выводятся:

- количество пропусков;
- минимум и максимум;
- среднее;
- дисперсия;
- квантили: `q05`, `q25`, `q50` (медиана), `q75`, `q95`;
- частотная гистограмма по фиксированному числу интервалов.

Для категориального признака выводятся:

- количество пропусков;
- список категорий;
- частотная гистограмма, в которой число столбцов равно числу категорий.

Гистограмма выводится в консоль в текстовом виде. Пример:

```text
Признак 0: age (числовой)

  пропусков: 0
  min: 17.000    max: 90.000
  mean: 38.582   var: 186.061

  q05: 19.000
  q25: 28.000
  q50: 37.000
  q75: 48.000
  q95: 63.000

  [17.0, 24.3)  ######################        142
  [24.3, 31.6)  ###################           121
  [31.6, 38.9)  ##########################    167
  ...
```

Требования к статистике:

1. Статистика вычисляется по исходным данным — до заполнения пропусков и любых
   преобразований. Пропущенные значения при расчёте статистик не участвуют.
2. Результаты анализа хранятся отдельно от самих данных и не изменяют датасет.
3. Некорректный ввод (не число, номер вне диапазона) обрабатывается без падения
   программы и без завершения цикла.

## 5. Предобработка

Перед выходом программа спрашивает пользователя, нужно ли сохранить
преобразованный датасет. При положительном ответе выполняется предобработка.

Предобработка включает три шага:

1. **Заполнение пропусков.** Числовые признаки — медианой, категориальные —
   дополнительной категорией (например, `__MISSING__`).
2. **Масштабирование числовых признаков.** Достаточно одного способа,
   выбранного вами, — например приведение к диапазону от нуля до единицы или
   стандартизация. Выбор описывается в README.
3. **Кодирование категориальных признаков.** One-hot или ordinal, на ваш выбор,
   с обоснованием в README.

Требования:

1. Заполнение пропусков использует уже вычисленную статистику. Медиана не
   пересчитывается по данным, в которые уже подставлены значения.
2. Информация об исходном наборе категорий не теряется при добавлении категории
   для пропусков.
3. Результат предобработки — плотная числовая матрица. После one-hot кодирования
   число столбцов матрицы может быть больше исходного числа признаков.
4. Вместе с матрицей хранится соответствие «номер столбца — имя признака», чтобы
   в следующих работах можно было понять, какому признаку соответствует столбец
   матрицы. Для one-hot столбцов используются составные имена вида `color_red`.

## 6. Сохранение результата

Итоговая матрица сохраняется в бинарном формате.

Значения сохраняются непосредственно как `double` в представлении IEEE 754, без
текстового преобразования.

Требования:

1. Формат содержит число строк, число столбцов, порядок хранения элементов и сам
   массив значений.
2. Реализованы и запись, и чтение. Есть тест: сохранить матрицу, загрузить её
   обратно и сравнить значения с исходными.
3. При загрузке сначала читаются размеры, под них выделяется память, и только
   затем читаются данные.
4. После сохранения программа выводит размеры обоих файлов в байтах:

```text
CSV:     184320 байт
Binary:   80664 байт
```

5. В README описывается, почему такой формат пригоден только для учебной задачи:
   он не учитывает размер типов на другой платформе, порядок байтов, версию
   формата и контроль целостности файла.

## 7. Требования к коду

- Стандарт C++20. Сборка через CMake, без предупреждений при `-Wall -Wextra`.
- Разделение на библиотеку ядра и консольное приложение: логика загрузки,
  анализа и преобразования лежит в библиотеке, ввод-вывод для пользователя — в
  приложении.
- Пропуски представляются через `std::optional`, разнотипные столбцы — через
  `std::variant` или эквивалентное решение с обоснованием.
- Стратегии обработки задаются через `enum class`, а не строками или
  «магическими» числами.
- Вычислительные функции (среднее, дисперсия, квантили) принимают данные через
  `std::span<const double>` или аналогичное невладеющее представление.
- Ошибки ввода-вывода и разбора обрабатываются осознанно: сообщение
  пользователю, а не аварийное завершение.
- Есть тесты, зарегистрированные в CTest. Специальный фреймворк не требуется:
  достаточно отдельной программы, которая проверяет утверждения и возвращает
  ненулевой код возврата при несовпадении. Минимальный набор проверок: разбор
  строки с пропуском, определение типа признака, расчёт квантилей на известном
  массиве, корректность кодирования категорий, цикл «запись — чтение» бинарного
  файла, реакция на несогласованный CSV.
- В Debug-конфигурации подключены AddressSanitizer и UndefinedBehaviorSanitizer,
  тесты проходят с ними без срабатываний.

# Задание со звёздочкой

Звёздочки нужны для автомата на теоретическом зачёте: если выполнены звёздочки
всех семи работ, зачёт ставится автоматом. На зачёт по самой лабораторной они не
влияют.

Задание выполняется полностью самостоятельно: код и проектные решения должны быть
вашими. Обращение к агенту здесь допустимо только за объяснениями языка и
библиотек, без генерации кода.

Звёздочка снимает жёсткую настройку программы: поведение начинает управляться
командной строкой, а стратегии предобработки становятся выбираемыми.

## 1. Параметры командной строки

Подключается header-only парсер аргументов (например,
[cxxopts](https://github.com/jarro2783/cxxopts)) и добавляются параметры:

| Параметр | Назначение |
|---|---|
| путь к датасету | входной CSV-файл |
| путь для сохранения | выходной файл с предобработанными данными |
| число интервалов гистограммы | вместо фиксированного значения в коде |
| стратегия заполнения числовых пропусков | среднее, медиана или ноль |
| способ масштабирования числовых признаков | min-max, стандартизация или robust |
| способ кодирования категориальных признаков | one-hot или ordinal |

Требования:

1. Есть вывод справки по параметрам.
2. Заданы разумные значения по умолчанию, при которых программа работает как в
   обязательной части.
3. Некорректные значения параметров приводят к понятному сообщению и коду
   возврата, отличному от нуля.
4. Стратегии внутри программы по-прежнему представлены `enum class`; разбор
   строки из командной строки в перечисление изолирован в одном месте и не
   размазан по коду обработки.

## 2. Три способа масштабирования

Реализуются три преобразования числового признака.

**Min-max:**

\[
x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}
\]

**Стандартизация:**

\[
x' = \frac{x - \mu}{\sigma}
\]

**Robust scaling** (устойчивое к выбросам, аналог
[RobustScaler](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.RobustScaler.html)):

\[
x' = \frac{x - Q_{0.5}}{Q_{0.75} - Q_{0.25}}
\]

Все нужные величины уже есть в вычисленной статистике — заново по данным они не
считаются. Отдельно обрабатывается вырожденный случай, когда знаменатель равен
нулю: поведение выбираете вы и описываете в README.

## 3. Два способа кодирования категорий

Реализуются оба варианта с переключением через параметр командной строки:

- **one-hot** — по столбцу на категорию, значения ноль или единица;
- **ordinal** — один столбец с целочисленным кодом категории.

Требования:

1. Порядок категорий при кодировании детерминирован: одинаковый вход даёт
   одинаковые номера столбцов и коды. Порядок описывается в README.
2. Имена столбцов итоговой матрицы соответствуют выбранному способу: составные
   вида `color_red` для one-hot, исходное имя признака для ordinal.
3. В README отмечено, для каких моделей ordinal-кодирование вносит ложный
   порядок между категориями, а для каких это несущественно.

## 4. Критерий выполнения звёздочки

Звёздочка считается выполненной, если:

- все параметры командной строки работают и влияют на результат;
- реализованы три стратегии заполнения пропусков, три способа масштабирования и
  два способа кодирования категорий, и переключение между ними действительно
  меняет выходные данные;
- вы можете объяснить каждую строку этого кода.
